# 一键日常启动器 v2.13.0

把「终末地 → 明日方舟 → 命运-冠位指定 → 鸣潮」四套日常挂机脚本按正确顺序拉起来的
Windows 小工具。双击一次，剩下的它自己排队执行，中途可以随时取消。

界面是 Python + Win32 自绘的单文件 exe，**不需要安装 Python / .NET / 运行库**，
拷贝一个 exe 就能启动 —— 但要让四个脚本真的跑起来，得先按下面的清单配一次。

---

## 新用户照着做（第一次用就从这里开始）

> **先说清楚：这个工具不是"下载完就能跑"。** 它只负责**按顺序帮你按按钮**，
> 每个脚本自己还要账号、关卡、分辨率、队伍。下面 8 步照着走，每一步都写了
> 「做对了是什么样」——卡住就对照那一条，比瞎试快得多。
>
> 全流程大约 40 分钟（大部分时间在等游戏下完、教程过完）。

### 第 1 步：确认机器够用

- Windows 10 / 11 x64
- 内存 **8 GB 以上**（两个模拟器同时开），磁盘留 **20 GB**
- 启动器放在**纯英文或纯中文、无空格**的路径，例如 `D:\tools\一键日常启动器\`

✅ 做对了：上面三行都满足。

---

### 第 2 步：装 MuMu 模拟器，建够实例

1. 到 <https://mumu.163.com/> 装 **MuMu 模拟器 12**（6.8.x 以上）；
2. 打开 MuMu → 右上角**多开器** → **新建实例**。

要同时跑明日方舟和 FGO，就建 **2 个实例**（实例 0、实例 1）。
只玩一个手游的话 **1 个也够** —— 启动器会自己认出你实际有几个实例，
不会像老版本那样干等一个不存在的实例 5 分钟。

✅ 做对了：`MuMu 安装目录\vms\` 下面有 `MuMuPlayer-12.0-0`（以及 `-1`）文件夹。

---

### 第 3 步：每个实例装游戏、登录、过教程

1. 在实例里装游戏：实例 0 装**明日方舟**，实例 1 装 **FGO**（反着装也行，第 7 步能指定）；
2. **手动登录账号**；
3. **把新手教程 / 序章 / 强制引导全部过完**，一直到能自由操作的主界面。

顺手记一下你的 FGO 是**哪个服**（B服 / 日服），第 7 步要选。

✅ 做对了：两个实例点开游戏都直接进主界面，不用再点「开始游戏 / 点击屏幕」。

> ⚠️ 这步跳过的后果：脚本会在登录页或新手引导上反复乱点，任务永远不完成，
> 而且日志里看不出来是这个问题。

---

### 第 4 步：装四个脚本

下载地址和版本要求见下面 **第二节「装好这些程序」**。
四个脚本解压/安装到任意目录即可，**先不要打开**。

✅ 做对了：四个目录里分别能看到 `MaaEnd.exe`、`MAA.exe`、`MaaFgo.exe`、`ok-ww.exe`。

---

### 第 5 步：每个脚本先手动跑通一次（最容易跳过，也最不能跳过）

| 脚本 | 你必须做的 | 做对了的标志 |
|---|---|---|
| **MAA** | 打开一次，等它加载完资源；配好「连接设置」（选 MuMu 12）；勾上你要刷的任务 | 目录里出现 `config\gui.json`，能手动跑完一次作战 |
| **MaaEnd** | 选「全套日常」实例；勾上「任务结束关闭游戏」 | 能手动跑完一轮，最后终末地自己关了 |
| **MaaFgo** | 选「默认设置」实例；勾好要跑的任务；模拟器分辨率固定 **1280×720**、系统语言**简体中文** | 能连上模拟器手动跑完一次 |
| **ok-ww** | 启动一次，等它自己把环境装好；确认每日任务能跑；`Basic Options → Exit App when Game Exits` 保持**关闭** | `data\apps\ok-ww\python\pythonw.exe` 和 `working\main.py` 都存在 |

✅ 做对了：四个脚本各自都能**在它自己的界面里**完整跑完一次日常。

> ⚠️ **没跑过的脚本，启动器只能把它"拉起来"，没法让它"自动开始任务"。**
> 尤其 MAA：没有 `config\gui.json` 时，启动器写不进"启动后直接运行"，你会看到
> 界面弹出来了却一直不动。ok-ww 更直接 —— 没跑过就没释放自带 Python，设置页
> **会拒绝保存它的路径**。

---

### 第 6 步：放好启动器，双击

1. 把 `一键日常启动器.exe`（和 `README.md`）放到**一个固定目录**，
   **以后别乱移、别改名** —— 移动会让免 UAC 的计划任务失效；
2. 双击运行，第一次会弹 **UAC**，点「是」；
3. 因为四个脚本的路径都还空着，程序**直接停在设置页，不会自动开跑**。

✅ 做对了：窗口打开就是设置页，日志区写着「还没配置好：已经在设置页了……」。

> 如果它直接开始跑了，说明目录里混进了别人的 `config.json`（别人的路径），
> 删掉它再打开。

---

### 第 7 步：在设置页把 9 行指对

前 5 行点右侧「选择」，挑**文件夹**就行（不用挑到 exe，程序会往下找三层）；
后 3 行点右侧的 **chip**，点一下换一个。

| 行 | 选什么 |
|---|---|
| MuMu 模拟器目录 | MuMu 安装目录，里面有 `nx_main` 的那一层 |
| MaaEnd · 终末地 | MaaEnd 所在文件夹 |
| MAA · 明日方舟 | MAA 所在文件夹 |
| MaaFgo · FGO | MaaFgo 所在文件夹 |
| ok-ww · 鸣潮 | ok-ww 所在文件夹（要有 `data\apps\ok-ww\`） |
| MAA 连哪台实例 | 明日方舟装在哪个实例就选哪个 |
| MaaFgo 连哪台实例 | FGO 装在哪个实例就选哪个 |
| FGO 版本 | B服 / 日服（别的服改 `config.json` 的 `maafgo.game_package`） |
| 检查更新 | 看看 GitHub 上有没有新版（详见「四、界面说明 → 自动更新」） |

✅ 做对了：每行下面显示的是**完整路径**，不再是「未设置」。
选完点左下「◀ 返回」回主界面。

> 选完如果消息里带「⚠ 这个 MAA 还没初始化过」，说明第 5 步没做，回去做。

---

### 第 8 步：点「一键启动」，看自检红字

1. 回主界面，六个勾选项按需要留（点一行就能勾/取消，**它记得住**）；
2. 点 **「▶ 一键启动」**；
3. 程序会先自检，把结果打在日志区：

| 日志 | 意思 | 怎么办 |
|---|---|---|
| `✗ 还没设置 MuMu 模拟器目录` | 第 7 步没选 MuMu | 回设置页选 |
| `✗ 找不到 xxx.exe` | 那个脚本路径不对 | 回设置页重选 |
| `✗ 实例2 在 MuMu 里不存在` | 配置里的实例号 > 你实际有的 | 点掉那一行，或去 MuMu 新建实例 |
| `⚠ MAA 还没初始化过` | 第 5 步没做 | 手动打开一次 MAA 跑通再回来 |
| `⚠ 当前不是管理员权限` | 免 UAC 没生效 | 看下面第三节「关于 UAC（重要）」 |

**能救的项它会自动跳过、其它照跑**（比如 MaaEnd 路径写错，两个模拟器照样启动）。

✅ 做对了：日志里没有 ✗，然后按 `MaaEnd → MuMu×N → MAA → MaaFgo → ok-ww`
自己排队跑完，最后一行是「—— 全部完成 ——」。

> **以后每次打开软件**，会先弹一张「按上次的勾选全部一键启动吗」的卡片（5 秒倒计时）：
> 点**「否」**只跑《今晚的手游日常》，点「取消启动」这次不跑，什么都不做就按上次的勾选全跑。
> 想事后补一次夜间启动，直接点主界面右下角的 **「夜间启动」** 按钮，效果和点「否」一样。
> 详见第四节「夜间启动」。

### 卡住时先看这张表

| 现象 | 真正的原因 | 怎么办 |
|---|---|---|
| 双击后一闪而过 | 上次异常退出留了僵尸进程占着单实例锁 | 再双击一次，弹窗选「是」；或任务管理器结束所有同名进程 |
| 又弹 UAC 了 | 移动过 exe / 改过名字，计划任务指旧路径 | 右键 `安装免UAC启动.bat` → 以管理员身份运行 |
| 脚本弹出来但一直不动 | 那个脚本没手动跑通过（缺 `gui.json` / 没配任务） | 回到第 5 步 |
| 卡在「等待安卓开机」 | 模拟器启动慢，或端口又漂了 | 看 `launcher.log` 里的「端口由 X 变为 Y」；等超时会跳过 |
| MaaFgo 连不上模拟器 | 设备地址端口不对 / 分辨率不是 1280×720 | 启动器会自动对齐端口；分辨率自己改 |
| 脚本在登录页乱点 | 账号没登录或教程没过 | 回到第 3 步 |
| 勾选状态不对 / 想重置 | —— | 点右上「全选」两下；或删掉 `config.json` 重新走向导 |

## 一、它能替你做什么

| 程序 | 游戏 | 它负责的事 |
|---|---|---|
| MaaEnd | 明日方舟：终末地（PC） | 全套日常，跑完自己关游戏 |
| MAA | 明日方舟（模拟器） | 基建换班、刷理智、收菜 |
| MaaFgo | 命运-冠位指定（模拟器） | 日常、刷本、关闭游戏 |
| ok-ww | 鸣潮（PC） | 每日任务一条龙 |
| MuMu 模拟器 | —— | 上面两个手游的载体 |

它会**按依赖顺序**启动它们、等上一步真的跑完再进下一步，最后根据各程序的日志
判断"任务跑完没有"，把用不上的模拟器关掉省资源 —— 但**四个程序本身一个都不关**，
方便你回头看日志。

### 2. 各自先手动跑通一次

**这一步别跳过。** 每个程序都有自己要配的东西（账号、关卡、队伍、分辨率），

- **ok-ww**：确认每日任务能跑，`Basic Options → Exit App when Game Exits` 保持**关闭**。

### 3. 系统要求

- Windows 10 / 11，x64
- 两个模拟器同时开大约需要 **8 GB 内存**、20 GB 磁盘
- 建议把本程序放在**纯英文或纯中文、无空格的路径**下，例如 `D:\tools\一键日常启动器\`

## 三、第一次使用

> 完整步骤见开头 **「新用户照着做」**。这一节只讲
> 程序在这几个环节具体做了什么，方便你判断"它是不是卡住了"。

1. **解压/拷贝** `一键日常启动器.exe` 到任意目录（它会在自己旁边生成
   `config.json` 和 `launcher.log`）。
2. **双击运行。** 第一次会弹一次 UAC —— 点「是」。
   为什么需要管理员：MuMu 的设备进程（`MuMuNxDevice.exe`）需要提权才能无提示启动，
   否则每开一个实例就弹一次 UAC。
3. 程序发现你**还没配好路径**（不是"文件在不在"，而是"四个脚本路径都空着"），
   会**直接停在设置页**（不会自动开跑），逐行指路。
4. 点**「◀ 返回」**回主界面，点**「▶ 一键启动」**。

### 启动前会自动自检

点「一键启动」时，程序会先体检一遍，把"路径指对了却还是跑不起来"的原因
直接写在日志区。**能救的就跳过那一项、其它照跑**（例如 MaaEnd 路径错，
不会连累模拟器），救不了的才停下来：

| 自检发现 | 它怎么说 | 怎么修 |
|---|---|---|
| MuMu 目录没设 / 选错层 | 「还没设置 MuMu 模拟器目录」/「找不到 nx_main\MuMuManager.exe」 | 设置 → MuMu 模拟器目录，选到 `MuMu Player 12` 这一层 |
| 实例数对不上 | 「实例2 在 MuMu 里不存在（实际只有 0、1）」 | 在 MuMu 里新建实例，或点掉那一行 |
| 脚本没初始化过 | 「MAA 还没初始化过（config 里没有 gui.json）」 | 先手动打开一次该脚本，配好连接和任务 |
| ok-ww 环境没释放 | 「找不到 pythonw.exe / working 目录不存在」 | 先手动启动一次 `ok-ww.exe`，等它自己装好 |
| 实例号配错 | 「MaaFgo 设的连接实例 1 不在实例列表里」 | 设置页点「MaaFgo 连哪台实例」换一台 |
| 没管理员权限 | 「MuMu 设备进程可能自己弹 UAC」 | 用 `安装免UAC启动.bat` 注册计划任务 |

> 自检只检查"程序这一侧"能不能跑。**游戏账号有没有登录、教程有没有过完、
> 脚本里关卡/队伍有没有配**，这些只有你自己知道，程序查不出来。

### 实例是自动识别的

程序会读 `MuMu 目录\vms\MuMuPlayer-12.0-N` 里**实际存在**的实例来生成列表，
不再写死"实例 0 + 实例 1"：

- 只建了 1 台 → 列表里就 1 行，不会白等另一台超时 5 分钟；
- 建了 3 台 → 列表里 3 行，可以单独勾；
- 配置里 MAA/MaaFgo 记的实例号如果越界（典型：只有 1 台，而 MaaFgo 默认写 1），
  会自动回落到现有的实例，并在日志里说明。

### 关于 UAC（重要）

第一次运行点完「是」之后，程序会**自动注册一个计划任务**（名字 `DailyLauncher`），
以后双击快捷方式就是**管理员权限且不弹 UAC**。

如果你后来**移动了程序目录**或**改了 exe 名字**，计划任务会失效，又会开始弹 UAC。
让它自动修复：以管理员身份运行一次，
或双击目录里的 `安装免UAC启动.bat`（右键 → 以管理员身份运行）。

### 六个勾选项

点任意一行可以单独勾选/取消。**没勾的项就是这一步不做**，
下面的步骤会自动跳过它（例如不勾 MaaEnd，就直接从模拟器开始）。

**它会记住你上次的勾选。** 改完自动写进 `config.json`，下次打开还是那样，
日志区第一行会写「已记住上次的勾选（N/6 项：…）」，没勾的行状态显示「本次跳过」。

想让它"下次别自动跑"，就把不想跑的项点掉 —— 不用每次重新选。
勾选状态同时存了一份 `config.json.bak`，万一主文件写坏（断电、强杀），
下次启动会自动从备份恢复，不会莫名其妙变回"全选"。

### 开机问一句：按上次的勾选全部一键启动吗？

**打开软件**（且开了「打开即启动」）时，会先弹一张卡片，5 秒倒计时：

```
┌────────────────────────────────────────────────────────────┐
│ 按上次的勾选全部一键启动吗？                      [4 秒]    │
│                                                            │
│ 否 = 只启动《今晚的手游日常》：明日方舟（MAA）、FGO（MaaFgo）│
│ 《今晚的手游日常》= 一天要清两次日常的手游（可在设置里改）  │
│ 不操作就等 5 秒，按上次的勾选全部启动                      │
│                                                            │
│          [  否  ]          [ 取消启动 ]                   │
└────────────────────────────────────────────────────────────┘
```

| 你的操作 | 结果 |
|---|---|
| 点 **「否」** | 不按上次勾选全跑，改为**只启动《今晚的手游日常》**（默认 = 明日方舟 MAA + FGO MaaFgo）。**勾选不改、不写进配置**，下次打开还是你原来的勾选 |
| 点 **「取消启动」** | 这次**什么都不启动**，卡片消失 |
| 什么都不做 | 5 秒后卡片自己消失，**按上次的勾选全部启动** |

**《今晚的手游日常》是什么**：一天体力要清**两次**、晚上不清第二天就溢出的那批手游。
默认是「明日方舟（MAA）+ FGO（MaaFgo）」，可以在设置里改（下一节）。

**事后想补一次夜间启动**（比如白天误点了全部启动、晚上想再清一轮）：
点主界面右下角的 **「夜间启动」** 按钮，效果和点「否」**完全一样** ——
两个入口走的是同一个函数 `night_start()`，都只跑《今晚的手游日常》，
都不动勾选、不写配置。启动过程中这个按钮会灰掉。

> 嫌 5 秒烦：`config.json` 里把 `night_prompt` 改成 `false`，打开软件就直接开跑。
> 连自动启动都不想要：把 `auto_start_on_launch` 改成 `false`，打开后手动点。

### 自动更新（检查 / 下载 / 安装）

设置页 **③ 其它 →「检查更新」**。整条流程都在程序里完成，不用去浏览器下载解压。

| 什么时候查 | 会不会打扰你 |
|---|---|
| **打开软件 3 秒后**自动查一次 | 不弹窗、不抢焦点，查到新版只在状态栏右边写一句 |
| 点设置页「检查更新」那一行 | 主动查，结果显示在同一行 |
| 点状态栏右边那句提示 | 直接跳到设置页，那一行就在「③ 其它」里 |

**它长什么样**（按状态自动变）：

| 状态 | 那一行显示 | 右边按钮 |
|---|---|---|
| 还没查 | 当前 v2.11.0 · 点右侧去 GitHub 看看有没有新版 | 检查 |
| 查到了新版 | 发现新版 v2.12.0 · 2026-11-02 发布，点右侧下载（约 8.4 MB） | 下载 |
| 正在下载 | 正在下载 v2.12.0：42%（共 8.4 MB）（别关窗口） | 下载中 |
| 下好了 | 新版 v2.12.0 已下载好，点右侧安装：程序会关闭、替换后自动重开 | 安装 |
| 已是最新 | 已经是最新（v2.11.0）· 点右侧再查一次 | 再查 |
| 出错 | 检查失败：连不上 GitHub（超时）· 点右侧重试 | 重试 |

**安装是怎么做的**（重点，出问题知道去哪儿找）：

1. 下载的 zip 和里面解出来的新 exe 都放在 exe 旁边的 `_update\` 目录；
2. 点「安装」后，程序用**新 exe** 起一个后台进程当"更新器"，然后自己关掉；
3. 更新器等旧进程退出（最多 40 秒），把老 exe 改名成 `一键日常启动器.exe.old`，
   再把新版复制到原来的位置，然后重新打开程序；
4. 下次启动时顺手清理 `_update\` 目录和 `.old` 备份。写不进新文件会自动回滚，
   全过程写进 `launcher.log`（搜「更新」两个字）。

几个注意：

- **它不是自动安装**。查到新版只会提示，装不装由你点。
- **正在跑任务时点「安装」会被拦下**，先「取消启动」或等这一轮跑完。
- 装完如果打不开，旁边的 `一键日常启动器.exe.old` 就是上一版，改回名字即可。
- 不想让它开机自动查：`config.json` 里 `check_update_on_launch` 改成 `false`
  （手动点「检查更新」照样能用）。
- 公司网/校园网连不上 GitHub 时，那一行会显示「连不上 GitHub（超时）」，
  这时可以手动去 [Releases 页面](https://github.com/cru77z7m/Mobile-game-daily-task-one-click-launcher/releases) 下载覆盖。
- **只认 Releases 里的最新版**，不会去拉分支代码；源码模式（直接用 python 跑）不支持自动替换。

### 「增加自定义实例」怎么用

设置 →「主界面项目（自定义 / 删除）」→「管理」→ 点「+ 增加自定义实例」→「添加」。

流程是**两步**：

1. 弹「浏览文件夹」框，选**脚本 exe 所在的文件夹**；
   里面只有一个 exe 就直接选中，有几个则弹一张卡片让你挑；
2. 同样地选**游戏启动 exe 所在的文件夹**，再挑一个（这一步可以取消）。

选完主界面会多出一行，格式是「未适配 · 只打开不自动跑 · 脚本.exe + 游戏.exe」。

⚠️ **自定义项是「未适配」的**：启动器只负责帮你**打开游戏和脚本**，
**不会**自动点「开始任务」、**不会**检测任务完成、跑完也**不会**帮你关游戏或关脚本。
任务要在脚本自己的界面里点开始 —— 添加时的日志里会再提醒一次。

最多加 4 个自定义项（再多主界面就挤不下了）。

> **为什么是「选文件夹」而不是「选文件」**：Windows 自带的"打开文件"框在这台机器上
> 弹不出来（`GetOpenFileNameW` 直接返回错误 87），只有"浏览文件夹"框正常。
> 所以启动器用两步代替：先选文件夹，再从里面挑 exe —— 交互和其它 5 项路径选择一致。

## 五、执行逻辑（它是怎么排队的）

```
① MaaEnd（终末地，PC 端）
      ↓ 读它的 debug 日志，等任务完成（实测约 85 分钟）
      ↓ 再等终末地游戏窗口消失
② MuMu 实例0（明日方舟）  ┐ 同时启动
③ MuMu 实例1（FGO）       ┘
④ 等两台模拟器的 Android 系统启动完成（adb sys.boot_completed = 1）
⑤ MAA：把配置里的 adb 地址改成实例0 的**实际端口**，然后启动
⑥ MaaFgo：实例1 里没开游戏就先帮你打开 FGO
      ↓ 等游戏进程真的起来，再多等 10 秒过启动画面
      ↓ 把 MaaFgo 里记的设备地址改成实例1 的实际端口
      ↓ 启动 MaaFgo 并自动开始任务
⑦ ok-ww：用自带的 Python 跑每日任务，界面一出来就自动开始
⑧ 收起「MuMu模拟器」主窗口（后台守候 120 秒，一冒头就收起）
⑨ 转入「后台完成监视」（见下一节）
```

**为什么必须串行：**

- **MaaEnd 一定要第一个**：它用 Win32 消息直接操作**电脑上的**终末地窗口
  （独占鼠标），和别的东西同时跑必然互相打断。
- **ok-ww 一定最后**：它也是 PC 端前台游戏（鸣潮），会和 MaaEnd 抢窗口。
- **MAA / MaaFgo 必须等模拟器起来**：它们走 ADB，实例没开就没得连。

**为什么端口要动态改：** MuMu 每次启动可能把 adb 端口在 16416/16417 之间换，
写死就会连错。启动器每次读取 `vm_config.json` 里的真实端口再写回各程序的配置。

## 六、跑完之后：关什么、留什么

| 对象 | 处理 | 原因 |
|---|---|---|
| **MuMu 实例 1** | MaaFgo 的任务一完成就关 | FGO 四分钟就刷完，留着白占两三 GB 内存 |
| **MuMu 实例 0** | MAA 的任务一完成就关 | 明日方舟要一个多小时 |
| **鸣潮游戏** | ok-ww 完成后退（正常关闭，不是强杀） | 省显卡 |
| **MaaEnd / MAA / MaaFgo / ok-ww** | **全部保留**，窗口和日志都在 | 方便回看这一轮跑成什么样 |

### 「任务完成」是怎么判断的

不是靠"进程还在不在"，而是**读各程序自己的日志**，而且只认**本次启动之后**写的行：

| 程序 | 日志文件 | 判定依据 |
|---|---|---|
| MAA | `MAA\debug\gui.log` | `任务已全部完成！` |
| MaaFgo | `MaaFgo\debug\<日期>-<N>.log` | `kind: tasks-completed` |
| ok-ww | `ok-ww\data\apps\ok-ww\working\logs\ok-script.log` | `end running onetime_task …` |

**MaaFgo 有个坑**：它的任务链会**分段**执行，一段跑完打一条完成标记，
十几秒后又开下一段。所以判定条件是「最后一次完成标记之后 **60 秒**内
没有再开新的一段」—— 这样最多晚一分钟关实例，但不会打断还在跑的任务。

> ok-ww 的完成标记默认不写（需要 debug 级日志）。启动器会自动在它的
> `working\` 目录放一个 `_launcher_auto.py` 入口来打开这个标记，
> 每次启动重写，**不要手动改它**。

## 七、配置文件 `config.json`

大多数情况用界面就行，想细调再动它。几个常用字段：

| 字段 | 含义 | 默认 |
|---|---|---|
| `mumu_root` | MuMu 安装目录 | —— |
| `maaend.path` / `maa.path` / `maafgo.path` / `okww.path` | 各程序 exe | —— |
| `maaend.instance` | MaaEnd 里要跑的实例名 | 全套日常 |
| `maafgo.instance` | MaaFgo 里要跑的实例名 | 默认设置 |
| `maafgo.emulator_index` | FGO 在哪台模拟器 | 1 |
| `maa.instance_index` | MAA 在哪台模拟器 | 0 |
| `okww.task` | ok-ww 要跑的任务 | DailyTask（每日任务） |
| `mumu_main_window` | 主窗口怎么处理：`hide` 收起 / `minimize` 最小化 / `keep` 不动 | hide |
| `shutdown_emulator_when_done` | 任务完成后关模拟器 | true |
| `okww.close_game_when_done` | ok-ww 完成后关鸣潮 | true |
| `monitor_poll` | 后台监视多少秒查一次日志 | 20 |
| `monitor_max_hours` | 最多监视多久 | 10 |
| `auto_start_on_launch` | 打开就自动开始 | true |
| `check_update_on_launch` | 打开软件 3 秒后悄悄查一次 GitHub 有没有新版（只在状态栏提示，不弹窗）；设 `false` 就不自动查 | true |
| `night_prompt` | 自动开始前先弹「按上次的勾选全部一键启动吗」询问卡（5 秒不回答就按勾选全跑）；设 `false` 就是直接开跑 | true |
| `night_items` | 《今晚的手游日常》包含哪些（`maa` / `maafgo` / `maaend` / `okww` / `custom:<id>`） | maa, maafgo |
| `custom_items` | 你自己加的项目：`{id, name, script, game, enabled}`，启动器只帮你打开 | 空 |
| `hidden_items` | 被你从主界面删掉的行（`maa` / `vm0` / `custom:<id>` …） | 空 |
| ⚠ 不再有 | `about` / `config_version` / `last_run_version` 已从 config.json 移出（见下） | —— |

`config.json` 里**只放你自己的东西**（路径、开关、勾选、自定义项）。

版本号这类程序内部状态在旁边的 `launcher.state.json` 里，作者信息写死在程序里。
v2.10.0 之前的版本把这三样混在 `config.json` 里，升级后第一次打开会自动搬走 +
清理干净（原文件备份成 `config.json.v<旧版本>.bak`），你不用管。

> 为什么分开：这三样东西用户既不该看、也不该改。放在同一个文件里，
> 手滑改坏一个数字就可能让程序判错版本、或者让「关于」页显示成别人的名字。

勾选状态也存在这个文件里（`enabled` 字段），所以**上次取消了哪几项，下次打开还是那样**。

## 八、发给别人 / 换一台电脑

**只发这两个文件：**

```
一键日常启动器.exe
README.md（建议给：对方照着「新用户照着做」那 8 步就能自己配完）
```

**千万别把 `config.json` 一起打包。** 它存的是**你这台机器**的路径
（`G:\Program Files\...`、`D:\Download\...`）和勾选状态，别人拿到后
打开就是满屏「找不到 xxx.exe」，还以为是程序坏了。删掉它，新用户第一次
打开会自动进设置向导。

换到自己另一台电脑也一样：删 `config.json` → 重新指路径。勾选状态会重置成
全勾，指完路径再按需要点掉。

对方拿到后要做的，就是文档开头那 8 步；其中**第 2、3、5 步程序替不了**：

- 第 2 步：MuMu 建够实例；
- 第 3 步：每个实例装游戏、登录账号、过完教程；
- 第 5 步：四个脚本各自手动跑通一次（MAA 要生成 `config\gui.json`，
  ok-ww 要释放自带 Python，MaaFgo 要 1280×720 + 简体中文）。

这三步做完，第 6～8 步（放 exe → 指路径 → 点启动）才走得通。

## 九、升级到新版本（直接覆盖 exe）

**可以，直接把新的 `一键日常启动器.exe` 覆盖掉旧的就行**，配置不会丢。

`config.json` 一直躺在 exe **旁边**，程序只读它、不碰 exe 自身，
所以换版本 = 换一个 exe 文件，跟配置没关系。升级后第一次打开，日志里会多一行：

```
已从 v2.7.1 升级到 v2.8.0：路径、勾选、自定义项都沿用，不用重新设置。
```

几点要注意：

1. **先关掉程序再覆盖**。exe 正在运行时 Windows 会锁住文件，复制会报
   「文件正在使用」。
2. **别换目录、别改文件名**。覆盖时保持路径和名字不变，免 UAC 的计划任务
   （`DailyLauncher`）还指着这个路径，改名/挪窝会让它失效（程序以管理员身份
   跑起来时会自动校正一次，但普通权限下不会）。
3. **不要顺手把 `config.json` 也删了**。它是你所有的路径和勾选。
4. 新版如果新增了配置项，会自动按默认值补上，**不会覆盖你已有的值**；
   真要改结构，程序会先把老配置备份成 `config.json.v<旧版本>.bak` 再迁移，
   并且写进 `launcher.log`。

也就是说：`config.json` 只跟"这台机器的路径"有关，跟"哪个版本的 exe"无关。
只有一种情况需要重配 —— 你把 exe 挪到了另一个文件夹，而 `config.json`
留在了原地。

> 想从零开始就删掉 `config.json`（下次启动会重新生成一份），
> 但删之前先复制一份当备份。

## 十、常见问题

**Q：双击没反应 / 一闪而过**
上一次异常退出留了僵尸进程占着单实例锁。再双击一次，程序会弹窗问你要不要清理；
选「是」。或者去任务管理器结束所有 `一键日常启动器.exe`。

**Q：又弹 UAC 了**
计划任务失效（移动过目录 / 改过 exe 名）。右键 `安装免UAC启动.bat` → 以管理员身份运行。

**Q：MAA 启动报「悲报：Nahimic AudioDevProps2.dll」**
Nahimic 音频驱动往所有进程里注入 DLL，被 MAA 检测到。启动器已经在安装时
自动给它关了扩展点注入（`Set-ProcessMitigation`）。如果还报，重新运行一次
`安装免UAC启动.bat`。

**Q：MaaFgo 连不上模拟器**
① 确认它配置里的设备地址端口和 MuMu 实际端口一致（启动器会自动改，前提是
`maafgo.sync_device_address = true`）；② 模拟器分辨率要是 1280×720。

**Q：卡在「等待安卓开机」**
模拟器启动慢或端口又变了。看 `launcher.log`，里面会写"端口由 X 变为 Y"。
超过设定的超时时间会跳过这一步。

**Q：怎么让它下次不要自动启动**
把 `config.json` 里 `auto_start_on_launch` 改成 `false`。

**Q：双击之后要等一下才有窗口，正常吗？**
正常。这是**单文件 exe** 的固有代价：每次启动都要先把内部约 12 MB 的
Python 运行时解压到临时目录（杀毒软件还会挨个扫一遍），然后才轮到程序自己跑。
v2.13.0 已经把能砍的都砍了（9.3 MB → 5.6 MB，约 1.3 秒 → 0.85 秒）。
机器上新装/刚更新完的那几次会慢一些，之后快。

> 为什么不做成"文件夹版"（秒开）：那样 `一键日常启动器.exe` 旁边必须跟着
> 一个 `_internal` 目录，拷给朋友、覆盖升级、自动更新都会变成"搬一整个文件夹"，
> 出错概率高很多。现在这个单文件"复制到哪都能跑、删掉就干净"。

**Q：覆盖 exe 升级后，路径和勾选还在吗？**
在。`config.json` 跟 exe 是分开的两个文件，覆盖 exe 不会动它。详见
「九、升级到新版本」。唯一会丢的情况是把 exe 挪到别的文件夹、把 config 留在原地。

**Q：升级后界面多了/少了几个设置项，是配置坏了吗？**
不是。新版新增的配置项会用默认值自动补上，你原来的值一个都不会被覆盖。

**Q：我把勾选改乱了 / 想恢复全选**
点右上角「全选」两下（先全灭再全勾），或者直接删掉 `config.json`，
下次启动会生成一份全勾的默认配置。

**Q：想看它到底干了什么**
同目录的 `launcher.log`，每行都有时间戳。

## 十一、目录里都有什么

```
一键日常启动器.exe     主程序（单文件，图标资源已内嵌）
config.json            配置和勾选状态（你的选择就记在这；删掉它 = 回到首次向导）
config.json.bak        它的自动备份，主文件坏了从这儿恢复
launcher.state.json    程序内部状态（配置结构版本、上次运行的版本号），不用管它
launcher.log           运行日志
_update\               自动更新时下载的发布包和新 exe（装完会自动清掉）
*.exe.old              自动更新留下的上一版 exe，确认新版没问题就可以删
安装免UAC启动.bat      重建计划任务 / 快捷方式 / MAA 注入防护（需管理员）
源码/                  想改的话看这里
README.md              本文件
```

> 分发时**只给 exe（和这份 README）**，不要带 `config.json` —— 详见第八节。
